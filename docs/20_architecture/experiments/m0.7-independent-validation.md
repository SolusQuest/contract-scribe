# M0.7 independent validation protocol

> **Status:** Historical M0 evidence. The exact identities, attempt semantics, aggregation, and post-merge ADR promotion below describe the completed Issue #10 protocol; they are not reusable requirements for current milestones. PR #77 removes this pipeline from ordinary CI, and Issue #75 removes its remaining current-tree provenance, aggregation, publication, and preservation-only machinery when no production consumer remains. Current production validation follows the pre-release engineering and active milestone rules without reproducing this evidence-publication lifecycle.

This record defines the M0.7 protocol for Issue #10. It validates the unchanged M0.6-selected framework-dependent semantic execution baseline against the public fixture [Yuee98/contract-scribe-m07-fixture](https://github.com/Yuee98/contract-scribe-m07-fixture) at commit [`aee85e30a7634fdf6adce7ac8b1a185a68b9698a`](https://github.com/Yuee98/contract-scribe-m07-fixture/commit/aee85e30a7634fdf6adce7ac8b1a185a68b9698a). The fixture manifest at that commit records the owner, public availability expectation, pre-run independence/public-safety review, protected file inventory, and SHA-256 values. The fixture source and canonical `expected-payload.json` oracle were committed before selected-baseline execution, with no trailing newline, and `.gitattributes` pins LF text checkout across required cells.

The selected baseline is ContractScribe commit [`645c0946b8b811d633b471b232b0654c10e6d7f6`](https://github.com/SolusQuest/contract-scribe/tree/645c0946b8b811d633b471b232b0654c10e6d7f6), with semantic source revision `63fd9a0ab5ff33ae20d8f7b9e66714a96feea39e` and transfer-manifest SHA-256 `1ad92419cf77e82f660cd1226f2a10dbb0561b6271b0bfc482a8bb4799237c7f`. M0.7 obtains a clean checkout of that commit, runs its unchanged M0.4 protocol/provenance checks there, and invokes its already-built host against the independent fixture. New M0.7 files are never admitted into the old M0.4 closed provenance file set.

The required cells are `ubuntu-latest` and `windows-latest` with X64 process architecture, SDK `10.0.102` under `latestFeature` roll-forward, the current M0.4 package baseline including `System.Security.Cryptography.Xml` `9.0.18`, and observed framework-dependent RIDs `linux-x64` and `win-x64`. The fixture preparation commands are `dotnet restore Sample.sln` followed by `dotnet build Sample.sln --configuration Release --no-restore`. Selected-baseline execution begins only after preparation and uses two fresh host processes per cell. The protocol declares no network-dependent operation and requires no private repository, provider credential, or write token; GitHub-hosted CI does not enforce network egress isolation, so this record does not claim a sandboxed offline run.

The independent oracle is the complete canonical payload. Each output must be UTF-8 without BOM, contain no trailing newline, match the oracle byte-for-byte, match the other fresh process in its cell, and match the other required cell. The verifier writes a bounded evidence record containing only identities, hashes, toolchain fields, RIDs, commands, comparison results, outcome classifications, CI identity, and unresolved risks. Aggregate independently hashes every retained payload against the manifest-pinned oracle and therefore does not trust an evidence-only `oracleEquality` declaration.

Current M0.7 terminal evidence is also bound to a GitHub Actions run attempt. Every success and bounded failure record carries `ci.runId` as a non-empty decimal string, `ci.runAttempt` as a positive JSON integer, the protocol PR head, validation merge SHA, protocol revision, and one closed cell identity: `Linux` with `linux-x64`, or `Windows` with `win-x64`. The writers resolve this identity before validation work through one rule: explicit test inputs take precedence; otherwise PR head is `M07_PR_HEAD_SHA`, then `pull_request.head.sha` from `GITHUB_EVENT_PATH`, then `inputs.pr_head_sha`, then `GITHUB_SHA`; validation merge is `M07_VALIDATION_MERGE_SHA`, then `GITHUB_SHA`; run ID, run attempt, and runner OS come from their corresponding GitHub variables. Required commit identities are lowercase 40-hex values, and absent, malformed, or contradictory identity is bounded `protocol-failure`. Local and synthetic tests provide identity explicitly.

Aggregation applies attempt semantics only to terminal records discovered under `EvidenceRoot`; it does not claim that the pinned artifact downloader exposes a complete inventory of every same-named artifact retained by GitHub. It first validates every discovered terminal envelope, including kind/outcome shape, run, positive non-future attempt, cell, PR head, merge SHA, protocol revision, selected baseline, fixture, oracle, and applicable provenance. Invalid or mixed provenance, unknown or cross-wired cells, and more than one discovered terminal record for the same `(run ID, runnerOs, rid, runAttempt)` fail closed before completeness is considered. Valid envelopes are grouped by required cell, and the numerically greatest attempt not greater than the aggregate attempt is selected independently for Linux and Windows; attempts may be sparse and the two cells may select different attempts. Complete payload, oracle, fresh-process, public-safety, and success-evidence validation applies only to selected successes. A valid-envelope superseded success need not retain payload files. Selected bounded failures retain the existing outcome precedence. `needs.validate.result` remains an independent necessary success gate, and aggregation never deletes local inputs or GitHub artifacts.

Every aggregate records `evidenceGeneratingRunId` and positive integer `evidenceGeneratingRunAttempt`. Once both cells have one unambiguous selected terminal record, it also records ordinal `cellSelections` entries containing `runnerOs`, `rid`, positive integer `selectedRunAttempt`, non-negative integer `supersededRecordCount`, and `highestSupersededRunAttempt`, which is `null` exactly when the count is zero. Selected-latest failure emits both selections; invalid identity, duplicate, conflict, or missing-cell failure before complete selection emits no partial `cellSelections`. Invalid attempt/cell/duplicate evidence maps to `protocol-failure` / `aggregate-evidence-invalid`; mixed provenance maps to `protocol-failure` / `aggregate-provenance-mismatch`; selected-baseline drift maps to `baseline-invalidated` / `aggregate-baseline-drift`; missing cell maps to `inconclusive` / `required-cell-evidence-incomplete`; non-success matrix result maps to `inconclusive` / `required-cell-validation-incomplete`; and selected bounded failure uses the precedence-selected existing outcome with `required-cell-failure`. These current v1 requirements do not reinterpret or rewrite attempt-less historical evidence, which remains bound to its pinned repository revision.

The lifecycle distinguishes the selected-baseline commit, semantic source revision, M0.7 protocol PR-head commit, validation merge-ref commit, evidence-generating CI run, evidence-publication commit, fixture/oracle commit, and later ADR-promotion commit. The PR-head commit identifies the protocol under review; the validation merge-ref commit identifies the exact checked-out commit used by CI and must match the evidence CI SHA. ADR 0001 remains provisional in the implementation PR; after merge and a successful post-merge main run, a separate follow-up PR promotes the ADR. Outcome classification is deterministic and non-overlapping: selected-baseline commit, semantic-source, transfer-manifest, frozen-host, runner, serializer, identity, or selected-baseline adaptation/drift is `baseline-invalidated` and returns the decision to M0.6; fixture, oracle, protocol-input, public-safety, or post-run evidence invalidation is `protocol-failure`; conforming semantic mismatch or nondeterminism is `baseline-failure`; missing or incompatible environment, cancellation, timeout, incomplete execution, or missing evidence before post-run validation is `inconclusive`; only complete positive evidence is `succeeded`. Aggregate precedence is `baseline-invalidated`, `protocol-failure`, `baseline-failure`, `inconclusive`, then `succeeded`, so every multi-cell result has one outcome.
