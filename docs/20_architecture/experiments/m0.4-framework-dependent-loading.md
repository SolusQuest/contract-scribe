# M0.4 framework-dependent Roslyn/MSBuild loading experiment

> **Status:** Historical M0 evidence. The commands, transfer manifest, hashes, allowlists, and M0.5 handoff below describe the protocol used to make the original decision; they are not current product validation requirements. Issue #75 removed the remaining current-tree experiment and preservation machinery. The original files remain available at the immutable commits linked by ADR 0001.

This record describes the public synthetic baseline for Issue #7. It is evidence for M0.5 and M0.6, not a production loader contract, audit-result contract, or distribution decision.

The fixture is `tests/fixtures/roslyn-msbuild/v1/Sample.sln`. It contains exactly two SDK-style C# projects: `SampleApp`, which has one project reference to `SampleLibrary`, and `SampleLibrary`. The expected graph and expected symbol set are handwritten in `expected-symbols.json`; the runner never generates its own oracle.

The semantic comparison artifact is the standalone `semantic-payload.json` file. It is written as UTF-8 without a BOM, whitespace, or trailing newline by a fixed `Utf8JsonWriter` property order. Projects and symbols use ordinal ordering. The comparison excludes environment, diagnostic, path, timestamp, duration, and process fields.

The original protocol restored once, built once with `dotnet build ContractScribe.slnx --configuration Release --no-restore`, ran `pwsh -NoProfile -File tests/ContractScribe.Roslyn.Experiment/verify-m0.4.ps1 -Configuration Release`, ran the manifest-tamper provenance regression, compared semantic payload bytes from two fresh host processes, and then ran focused and full repository validation. The verification script validated fixture and protocol-input hashes, central package declarations, result-envelope toolchain identity, expected payload SHA-256, public-safety constraints, and the no-restore run boundary on Ubuntu and Windows.

The accepted `9.0.18` Windows evidence instance consists of two successful fresh-process runs with identical payload SHA-256 `e5d3bc87a0448da6e953956aae897b33738a16efbedfeeefe1366fc5b8afbd29`. The observed toolchain identity is SDK `10.0.102`, MSBuild file version `18.0.7.61305`, discovery type `DotNetSdk`, runtime `10.0.2`, and process architecture `X64`. The original matrix reproduced the payload and protocol on both required cells; current pull requests do not maintain that historical hash gate.

The historical M0.5 handoff consisted of the fixture, expected oracle, semantic runner behavior, `(logicalProjectId, documentationCommentId)` identity, semantic payload, and ordering. Its frozen-artifact rule described the original experiment only and does not require a new pre-release baseline when current production code changes.

The transfer manifest records the package/SDK baseline, commands, comparison contract, content hashes, known warnings, unresolved constraints, and public-safe evidence boundary.
